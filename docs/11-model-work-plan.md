## Task routing policy

These are project recommendations, not measured model benchmarks. Select a model
for the work, then use the smallest effort that meets its acceptance evidence.
Effort names are not equivalent across providers.

| Work | First choice | Other client when its included usage is preferable | Boundary |
| --- | --- | --- | --- |
| Mechanical edits, fixtures, documentation after the contract is settled | Luna, low | Haiku; no adaptive effort assumed | No ownership of persistence ordering, query resource policy or architecture |
| Bounded feature implementation and regression fixes | Sol 6.1, medium | Sonnet, medium | Clear input/output contract and runnable acceptance check |
| Durability, cancellation, query resource bounds, retry/replay or cross-crate integration | Sol 6.1, high | Sonnet high or Opus medium for a focused review | Explicit failure cases and minimal file scope |
| Unresolved reasoning after a concrete failing test or conflicting invariants | Astra, medium, then high only if needed | Opus high; Fable only with separately authorized billing | Short investigation packet and stop condition |

Default implementation is Sol 6.1 medium. Sonnet medium is an equivalent workflow
option when Claude Max has more included capacity. Keep the chosen writer for a
phase so context need not be rebuilt. Do not implement the same task twice to
compare providers. Use one focused phase review; critical checkpoint decisions get
an explicit review before acceptance, included in that phase's review packet.

For mechanical work, one unsuccessful correction of the same understood issue
triggers reassignment to the implementation tier. Escalate directly on reproduced
loss, an unbounded allocation, or unclear commit/cancellation behavior. Compiler,
network, Docker, credential and permission failures require diagnosing the actual
boundary; increasing model strength does not remove an unavailable environment.
Max/Ultra and agent teams are not default routes. Earlier phase evidence used
explicitly authorized bounded teams. Delegate only when the current user request
authorizes agents; use one writer, focused review where required, and a settled
documentation pass. Finish accepted agents instead of repeated coordination.

## Invocation examples and execution discipline

These commands select a route for a newly launched task. Normal sessions now
inherit the project medium defaults. Flags avoid editing global defaults; an
existing active session retains its selected model/effort. Preserve current permissions. Standard speed is recommended
for planned runs; verify speed in the actual client. Project settings select Standard speed. Per-task routing does not enable
Fast/Ultrafast or bypass approvals.

```bash
# Mechanical task
codex -m gpt-6-luna -c 'model_reasoning_effort="low"'

# Normal Rust feature
codex -m gpt-6.1-sol -c 'model_reasoning_effort="medium"'

# Durability/integration task
codex -m gpt-6.1-sol -c 'model_reasoning_effort="high"'

# Claude implementation and focused critical review, when included/available
claude --model sonnet --effort medium
claude --model opus --effort medium

# Simple Claude task; Haiku adaptive effort is not assumed
claude --model haiku
```

CLI flags were checked against the installed clients and current Context7 docs.
[Codex model invocation](https://learn.chatgpt.com/docs/models),
[Claude session model/effort flags](https://code.claude.com/docs/en/model-config).

A task packet contains only:

1. Task ID, phase, selected actual model/effort and owned paths.
2. Relevant contract/ADR excerpts and current progress; avoid replaying a whole transcript.
3. Expected failure cases, measurable acceptance command and stop condition.
4. No-stage/no-commit instruction and any external evidence boundary.

Record actual model, usage/tokens if exposed, elapsed time, retries/escalations,
changed paths and test evidence in the phase handoff. Use CLI/local tests for bulk
processing: a model writes the million-event harness; it never consumes a million
rows as prompt context. Fetch Context7 by concept and summarize verbose compiler,
benchmark and scan output. Reuse a context within a coherent phase, then hand off
with a short evidence packet when the phase or writer changes.

Run targeted regressions during implementation, then the three required Cargo
gates, dependency-boundary check and the 14-point review once the phase is ready.
Rerun only gates affected by subsequent corrections. Validate actual untracked
files: `git diff` alone cannot show the current unborn repository's changes.
Measure cost per accepted task, including failed attempts and review, using the snapshot helper in [08](08-development-tooling.md), and adjust
the route after comparable accepted tasks. Do not buy a second provider subscription or add MCPs for
cost optimization when the existing clients, Context7 and direct shell cover the work.
